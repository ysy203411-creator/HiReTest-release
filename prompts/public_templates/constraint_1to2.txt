The generated test cases are used to test a C-like language compiler.
1. The program structure of the test case must start with several global declarations (constants or variables), optionally followed by several function definitions, and must end with exactly one main function: int main() {{ ... return 0; }}. The main function must explicitly include "return 0;" at its end, and the return value must be the literal 0.
2. All identifiers (variable names, constant names, function names) must be declared before use; all identifiers in the global scope (including functions, variables, and constants) must not be duplicated; there must be no duplicate identifiers in the local scope; inner scopes may shadow outer scope identifiers with the same name.
3. Constants (declared with const) must be initialized at the time of declaration, and the initial value must be a constant expression (i.e., composed solely of integer literals, previously declared constants, and arithmetic expressions that can be evaluated at compile time); constants cannot be assigned to, and cannot appear as the left-hand side of an assignment statement.
4. Global variables that are not initialized default to 0; if initialized, the initial value must be a constant expression. For global variable arrays or constant arrays, if the initialization list does not provide all elements, the remaining elements are default-initialized to 0. Local variables may be uninitialized (with undefined values); if initialized, the initial value can be any expression.
5. The use of static is allowed to modify local variables, but not for global variables. Static local variables that are not initialized default to 0 and are initialized only once; their scope remains limited to the function in which they are defined.
6. Arrays must be one-dimensional, and their length must be a non-negative integer constant expression that can be evaluated at compile time. Array access must include an index expression (e.g., a[i]), and cannot be multidimensional or omitted.
7. Functions can be of type int or void. For int functions, the last line of the function body must explicitly contain a return statement with a return value, even if it is unreachable. Void functions can only contain "return;" and may not have a return statement. Return statements may be unreachable.
8. Function parameter types can only be int or int[]. If the formal parameter is int, the actual argument must be an integer expression (variable, constant, or array element); if the formal parameter is int[], the actual argument must be a variable array name (not a constant array, nor a regular variable).
9. Expressions support arithmetic (+ - * / %), relational (== != < > <= >=), and logical (! && ||) operations. Multiple unary operators (+, -, !) can be used consecutively, but two identical operators cannot be adjacent (e.g., --i, !!a are invalid). The ! operator can only be used in conditional expressions. The results of relational and logical operations are 1 (true) or 0 (false); in conditional judgments, non-zero values are considered true, and 0 is considered false; the precedence, associativity, and short-circuit evaluation rules are the same as in C.
10. Statements include assignment, expression, statement block, if, for, break, continue, return, and printf. Among these: the left-hand side of an assignment statement must be a modifiable variable (not a constant); break and continue can only appear in for loops (directly or nested); SysY programs can call two runtime library functions: getint() (no parameters, returns int) and printf(StringConst, Exp, ...). StringConst is a string constant, containing only ASCII characters (codes 32, 33, 35–126) and escape sequences \\n; format specifiers only support %d, and the number of %d must match the number of subsequent integer expression parameters. Although the string constant type exceeds SysY (which only supports int and int[]), the compiler must correctly handle such calls. These two functions can be used without explicit declaration. Lexically, identifiers consist of letters, digits, and underscores, and cannot start with a digit; reserved words (such as int, const, if, for, etc.) cannot be used as identifiers; the comment syntax is consistent with C.
11. The ++ and -- operators are not supported, nor are compound assignment operators (+=, =, *=, /=, %=).
12. The types and number of parameters in a function call must match the function declaration.
13. Relational operators (== != < > <= >=) and logical operators (! && ||) [can only] appear in the condition expressions of if and for statements; they cannot appear on the right-hand side of assignment statements, in arithmetic expressions, function parameters, or the return values of return statements.
II. Constraints for error programs
Error programs are used to test the error detection capability of student compilers and must contain only one or more of the following clearly defined errors, and the error forms must strictly conform to their definitions.
a-type error: A single & or | appears in the source program, which should be considered an illegal symbol (it should be && or ||). The use of && or || must follow their usage rules, and they can only appear in conditional expressions.
Error programs must satisfy the following constraints:
Each line can contain at most one error;
There will be no "malicious line breaks" (e.g., intentional line breaks in strings, function calls, etc., to make errors hard to locate);
Errors will not appear in for statements to avoid syntactic ambiguity;
The parts of the program other than the error should ensure syntactic and semantic correctness to ensure the error can be accurately identified;
No other errors (such as illegal escapes, illegal identifiers, use of pointers, while, etc.) are allowed besides the above errors.
