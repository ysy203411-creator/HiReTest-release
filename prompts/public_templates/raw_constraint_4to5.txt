# 1. Overview

SysY is the source language for the compiler implemented in the compiler technology experiment, which is a subset of the C language. A SysY source file contains exactly one definition of the main function named `main`. Besides that, it may contain several global variable declarations, constant declarations and other function definitions. SysY supports the 32-bit signed integer type `int` and its one-dimensional array type. The `const` qualifier is used to declare constants.

SysY itself provides no built-in constructs for input/output (I/O). I/O is provided via a runtime library, and library functions can be invoked inside functions in SysY programs. The parameter types of some SysY runtime library functions may go beyond the data types supported by SysY, e.g., string literals. The SysY compiler must handle such cases and correctly pass these parameters from SysY programs to the SysY runtime library.

- **Functions**: A function may or may not have parameters. Parameter types can be `int` or its one-dimensional array type. A function may return an `int` value or return nothing (declared as `void`). When a parameter is of type `int`, pass-by-value is used. When a parameter is an array type, the starting address of the array is actually passed. A function body consists of a set of variable declarations and statements.
- **Variable / Constant Declarations**: Multiple variables or constants may be declared in one declaration statement, and initializer expressions may be provided upon declaration. All variables and constants must be defined before use. Declarations outside functions define global variables/constants; declarations inside functions define local variables/constants.
- **Statements**: Statements include assignment statements, expression statements (the expression may be empty), blocks, `if` statements, `for` statements, `break`, `continue`, and `return` statements. A block may contain multiple variable declarations and statements.
- **Expressions**: Basic arithmetic operators (`+`, `-`, `*`, `/`, `%`), relational operators (`==`, `!=`, `<`, `>`, `<=`, `>=`) and logical operators (`!`, `&&`, `||`) are supported. Non-zero values represent true, and zero represents false. The result of relational or logical evaluation uses `1` for true and `0` for false.> 
> **Operator precedence, associativity and evaluation rules (including short-circuit evaluation for logical operators) are identical to those of C.**

# 2. Runtime Library

Source programs perform I/O via `getint` and `printf`. To test programs in C, simply add the declaration and definition of `getint` as shown below:

```
int getint() {
int t;
scanf("%d",&t);
while(getchar()!='\n');
return t;
}
```

The syntax for `printf` is `'printf' '(' <StringConst> {, <Exp>} ')'`, where `StringConst` denotes the string constant terminal symbol. Its specification refers to Chapter 3 Grammar and Test Coverage Requirement, Section 3.5 String Constants. Parsing `<StringConst>` involves data types outside SysY’s supported type system, and the SysY compiler must handle this case.

# 3. Grammar and Test Coverage Requirements

## 3.1 Grammar

The grammar of SysY is written in Extended Backus–Naur Form (EBNF):

- `[...]`: items enclosed in square brackets are optional
- `{...}`: items enclosed in curly braces may appear zero or more times
- Terminals are either quoted strings or tokens such as `Ident`, `IntConst`, `StringConst`
- All single-quoted strings like `'main'` are reserved keywords

The SysY grammar is listed below, with `CompUnit` as the start symbol:

> 
> **Important: Semantic constraints in Section 3 of the grammar should be consulted alongside.**

```
CompUnit → {Decl} {FuncDef} MainFuncDef // 1.whether Decl exists 2.whether FuncDef exists
Decl → ConstDecl | VarDecl // covers two kinds of declarations
ConstDecl → 'const' BType ConstDef { ',' ConstDef } ';' // 1.zero repetitions inside braces 2.multiple repetitions
BType → 'int'
ConstDef → Ident [ '[' ConstExp ']' ] '=' ConstInitVal // covers scalar variables and 1D arrays
ConstInitVal → ConstExp | '{' [ ConstExp { ',' ConstExp } ] '}' // 1.constant expression initializer 2.1D array initializer
VarDecl → [ 'static' ] BType VarDef { ',' VarDef } ';' // 1.zero repetitions inside braces 2.multiple repetitions
VarDef → Ident [ '[' ConstExp ']' ] | Ident [ '[' ConstExp ']' ] '=' InitVal // scalar and 1D array definitions
InitVal → Exp | '{' [ Exp { ',' Exp } ] '}' // 1.expression initializer 2.1D array initializer
FuncDef → FuncType Ident '(' [FuncFParams] ')' Block // 1.no formal parameters 2.with formal parameters
MainFuncDef → 'int' 'main' '(' ')' Block // main function exists
FuncType → 'void' | 'int' // two function return types
FuncFParams → FuncFParam { ',' FuncFParam } // 1.zero repetitions inside braces 2.multiple repetitions
FuncFParam → BType Ident ['[' ']'] // 1.scalar variable 2.1D array variable
Block → '{' { BlockItem } '}' // 1.zero repetitions inside braces 2.multiple repetitions
BlockItem → Decl | Stmt // two kinds of block items
Stmt → LVal '=' Exp ';' // all statement types must be covered
| [Exp] ';' // two cases: with/without Exp; used for printf calls
| Block
| 'if' '(' Cond ')' Stmt [ 'else' Stmt ] // 1.with else 2.without else
| 'for' '(' [ForStmt] ';' [Cond] ';' [ForStmt] ')' Stmt // 1.no omissions, 1 case; 2.one omitted among ForStmt and Cond,3 cases;3.two omitted among ForStmt and Cond,3 cases;4.all omitted,1 case
| 'break' ';'
| 'continue' ';'
| 'return' [Exp] ';' //1.with Exp 2.without Exp
| 'printf' '(' StringConst {',' Exp} ')' ';' //1.with Exp 2.without Exp
ForStmt → LVal '=' Exp { ',' LVal '=' Exp } //1.zero repetitions inside braces 2.multiple repetitions
Exp → AddExp // existence suffices
Cond → LOrExp // existence suffices
LVal → Ident ['[' Exp ']'] //1.scalar variable/constant 2.1D array element
PrimaryExp → '(' Exp ')' | LVal | Number
Number → IntConst // existence suffices
UnaryExp → PrimaryExp | Ident '(' [FuncRParams] ')' | UnaryOp UnaryExp // all three cases must be covered; function calls cover variants of FuncRParams
UnaryOp → '+' | '−' | '!' Note: '!' only appears in conditional expressions // all three operators must be covered
FuncRParams → Exp { ',' Exp } //1.zero repetitions inside braces 2.multiple repetitions 3.Exp covers full/partial array passing
MulExp → UnaryExp | MulExp ('*' | '/' | '%') UnaryExp //1.UnaryExp 2.* 3./ 4.% all covered
AddExp → MulExp | AddExp ('+' | '−') MulExp //1.MulExp 2.+ covered 3.- covered
RelExp → AddExp | RelExp ('<' | '>' | '<=' | '>=') AddExp //1.AddExp 2.< 3.> 4.<= 5.>= all covered
EqExp → RelExp | EqExp ('==' | '!=') RelExp //1.RelExp 2.== 3.!= all covered
LAndExp → EqExp | LAndExp '&&' EqExp //1.EqExp 2.&& covered
LOrExp → LAndExp | LOrExp '||' LAndExp //1.LAndExp 2.|| covered
ConstExp → AddExp Note: Ident used must refer to constants // existence suffices
```

### 3.2 Supplementary Notes

#### (1) Identifiers `Ident`

The specification for identifiers in SysY:

```
identifier → identifier-nondigit
| identifier identifier-nondigit
| identifier digit
```

where `identifier-nondigit` is underscore or upper/lowercase letter; `digit` is digits from 0 to 9.

Reference: ISO/IEC 9899 [http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf](http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf) page 51 for identifier rules and **identical-name identifier** conventions:

- Scopes of global variables/constants and local variables/constants may overlap; in overlapping regions, local variables/constants take precedence.
- Scopes of local variables with identical names cannot overlap; i.e., no duplicate identifiers (constants/variables) within one `Block`.
- Variables/constants in SysY may share names with function identifiers under different scopes.
- Reserved keywords cannot be used as identifiers.

```
// Valid example
int main() {
	int a = 0;
	{
		int a = 1;
		printf("%d",a); // outputs 1
	}
	return 0;
}
```

```
// Invalid example
int main() {
	int a = 0;
	{
		int a = 1;
		int a = 2; // INVALID!
	}
	return 0;
}
```

#### (2) Comments

SysY comment rules match C:

- Single-line comment: starts with `//`, ends at newline character (newline excluded).
- Multi-line comment: starts with `/*`, ends at the first occurrence of `*/` (the terminating `*/` is included).

Reference: ISO/IEC 9899 [http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf](http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf) page 66 for comment definition.

#### (3) Numeric Constants

Numeric constants in SysY are integer constants `IntConst`:

```
integer-const → decimal-const | 0
• decimal-const → nonzero-digit | decimal-const digit
• nonzero-digit: digits from 1 to 9
```

Reference: ISO/IEC 9899 [http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf](http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf) page 54 for integer constants; all suffixes are ignored.

#### (4) String Constants

Definition of `<StringConst>` in SysY:

```
<FormatChar> → %d
<NormalChar> → ASCII characters with decimal codes 32,33,35-126; backslash '\' (code 92) appears only in '\n'
<Char> → <FormatChar> | <NormalChar>
<StringConst> → '"'{<Char>}'"'
```

Only one escape sequence `\n` is allowed inside strings to denote line breaks. No other escape sequences need to be handled.

# 4. Semantic Constraints

The set of programs accepted by the above grammar is a superset of valid SysY programs. Additional semantic constraints are defined below.

## Runtime Library

1. **To reduce implementation difficulty, all test programs guarantee that `getint` and `printf` are only used as runtime library calls and will never be used as user-defined variable/function identifiers.**
2. `printf` does not append a newline by default.
3. Similar to C `printf`, format specifiers in output statements are substituted with corresponding values, while ordinary characters are printed verbatim.

## `static` Keyword

1. `static` modifies **static local variables** and never appears on global variable definitions.
2. If a `static` variable declaration has an initializer, the initial value can be computed at compile time.
3. If a `static` variable declaration has no explicit initializer, **the compiler initializes it to zero**.
4. A `static` variable is initialized exactly once and **retains its state across subsequent invocations of the function**; it is not destroyed when exiting the function. Its scope is limited to the function where it is declared.

## Compilation Unit `CompUnit`

```
CompUnit → {Decl} {FuncDef} MainFuncDef
Decl → ConstDecl | VarDecl
```

1. Top-level variable/constant declarations (`Decl`) and function definitions (`FuncDef`) inside one `CompUnit` cannot redefine identifiers with identical names, even if their types differ.
2. The scope of variables, constants and functions in a `CompUnit` starts at the declaration point and extends to the end of the source file.

## Constant Definition `ConstDef`

```
ConstDef → Ident [ '[' ConstExp ']' ] '=' ConstInitVal
```

1. `ConstDef` defines a symbolic constant. `Ident` is the constant name. The optional 1D array and length specifier appears between `Ident` and `=`, followed by the initializer. Constants **must have initializers**.
2. When no array specifier is present, a scalar constant is defined.
3. When the array specifier exists, a constant array is defined. Semantics match C; indices start at 0.
4. Every `ConstExp` used for array lengths must evaluate to a **non-negative integer at compile time**.

## Variable Definition `VarDef`

```
VarDef → Ident [ '[' ConstExp ']' ] | Ident [ '[' ConstExp ']' ] '=' InitVal
```

1. Variable definitions are mostly identical to constant definitions, but variables may omit initializers; in such cases the runtime initial value is undefined.

## Initializers `ConstInitVal` / `InitVal`

```
ConstInitVal → ConstExp | '{' [ ConstExp { ',' ConstExp } ] '}'
InitVal → Exp | '{' [ Exp { ',' Exp } ] '}' | StringConst
```

1. Initializer expressions for constants must be constant expressions `ConstExp`.
2. **Constants must have initializers. Constant arrays do not require every element to be explicitly initialized; unassigned elements are zero-filled by the compiler.**
3. Initializer expressions for global variables must also be `ConstExp`. Local variable initializers are `Exp` and may reference previously declared variables.
4. For scalar constants or variables, the initializer must be a single expression (expressions include literals, single variables, single constants, etc.)
5. **Global variables without explicit initializers are zero-initialized; local variables are not.**

## Formal Parameters `FuncFParam` and Actual Parameters `FuncRParams`

```
FuncFParams → FuncFParam { ',' FuncFParam }
FuncRParams → Exp { ',' Exp }
```

1. `FuncFParam` defines one formal parameter. The optional bracket syntax after `Ident` denotes array parameters.
2. The syntax for actual arguments is `Exp`. Scalar variables use pass-by-value. For array-typed parameters, the formal parameter receives the address of the argument array and accesses array elements indirectly via the address.
3. Ordinary constants may be passed as function arguments, but constant arrays cannot. Example: `const int arr[3] = {1,2,3}`; the constant array `arr` cannot be passed into a function.
4. Function calls require matching types between actual arguments and formal parameters. See example below:

```
void f1(int x){
	return ;
}
void f2(int x[]){
	return ;
}
int main(){
	int x = 10;
	int t[5] = {1, 2, 3, 4, 5};
	f1(x); // valid
	f1(t[0]); // valid
	f1(t); // invalid
	f2(t); // valid
}
```

## Function Definition `FuncDef`

```
FuncDef → FuncType Ident '(' [FuncFParams] ')' Block
```

1. `FuncDef` defines a function. `FuncType` specifies the return type. When return type is `int`, all branches inside the function must contain `return` with an `Exp`. Branches without `return` yield undefined return values. When return type is `void`, only `return` without a return value may appear inside the function.
2. Semantics of `FuncFParams` are described above.

## Block `Block`

1. A `Block` introduces a scope. Constants and variables declared inside the block live only within the block.
2. Variables/constants with names identical to those outside the block may be re-declared inside the block via `Decl`. Their scope starts at definition and ends at block termination, shadowing outer identifiers of the same name.
3. **To reduce development effort: all test programs guarantee that functions with return values will have an explicit `return` statement as the last statement of their block; missing return statements are treated as errors. Sample programs written by students must follow this rule.**
4. The return value of `main` must be constant `0`.

## Statement `Stmt`

1. `if` statements use the dangling-else rule (nearest match).
2. A bare `Exp` may serve as a `Stmt`. The expression is evaluated and its value discarded.

## Lvalue `LVal`

1. `LVal` denotes an lvalue expression: a variable or an array element.
2. When `LVal` refers to an array, the number of brackets must match the dimension count of the array variable (to select an element).
3. When `LVal` refers to a scalar variable, no trailing brackets may appear.

## `Exp` and `Cond`

1. **`Exp` in SysY denotes expressions of `int` or `void` type; `Cond` denotes conditional expressions and is defined as `LOrExp`. The unary operators inside `Exp` exclude `!`, while `Cond` may use `!`.**
2. `LVal` must refer to variables or constants defined in the current scope before this expression statement. The lvalue on the left-hand side of assignment must be a variable.
3. Function calls take the form `Ident ‘(’ FuncRParams ‘)’`. The number and types of actual parameters must exactly match the formal parameters in the corresponding function definition.
4. Operator precedence and associativity in SysY match C, as encoded in the SysY grammar above.

## Unary Expression `UnaryExp`

1. Two identical consecutive `UnaryOp` are forbidden. Example: `int a = ++-i;` is invalid, but `int a = +-+i;` is allowed.
2. The `!` operator may only appear inside conditional expressions.

## Constant Expression `ConstExp`

1. **`ConstExp` in SysY denotes an `int` expression.**
2. `ConstExp` must be evaluable at compile time. All `Ident` referenced inside `ConstExp → AddExp` must be constants, i.e., only literals, named constants with known values, and arithmetic expressions composed from them can be used; evaluation must be computable by the compiler.

# 6. Error Handling

Starting from the lexical analysis assignment, all assignments require your compiler to handle both valid and erroneous programs. For valid programs, produce correct outputs as required; for erroneous programs, output the line number and error code for every error.

Errors fall into three categories: lexical errors, syntax errors, semantic errors. You must implement error handling for all three categories before emitting error messages.

## Error Type List

Category `a`: lexical analysis errors.
Categories `i,j,k`: syntax analysis errors.
All remaining categories: semantic analysis errors.

| Error Description | Error Code | Explanation | Relevant Grammar Rules and Symbols |
| --- | --- | --- | --- |
| Illegal symbol | a | Occurrence of `&` and `\|`. They should be treated as `&&` and `\|\|`, but token names are still recorded as `&` and `\|` | LAndExp → LAndExp '&&' EqExp   LOrExp → LOrExp '\|\|' LAndExp |
| Redefined identifier | b | Redefinition of function or variable name **within current scope**. Note: error only occurs in the same scope; inner scopes shadow outer definitions. | ConstDef → Ident …   VarDef → … Ident … Ident …   FuncDef → FuncType Ident …   FuncFParam → BType Ident ... |
| Undefined name | c | Use of undefined identifier; error line number is the line containing `Ident`. | LVal → Ident …   UnaryExp → Ident … |
| Mismatched number of function arguments | d | The number of arguments in function call does not match the function definition. | UnaryExp → Ident ‘(’ [FuncRParams] ‘)’ |
| Mismatched function argument type | e | Argument type mismatch at corresponding position in function call. Details below. | UnaryExp → Ident ‘(’ [FuncRParams] ‘)’ |
| Mismatched return statement in void function | f | A function without return value contains a return statement carrying a value. | Stmt → ‘return’ { ‘[’ Exp ’]’ } ‘;’ |
| Missing return statement in non-void function | g | Only check whether the last statement of function body is return; **control flow analysis is not required.** | FuncDef → FuncType Ident ‘(’[FuncFParams]‘)’ Block   MainFuncDef → 'int' 'main' '('')' Block |
| Modification of constant value | h | Assignment to an lvalue that is a constant. | Stmt → LVal ‘=’ Exp ‘;’   ForStmt → LVal '=' Exp … |
| Missing semicolon | i | Missing semicolon | `;` inside Stmt, ConstDecl, VarDecl |
| Missing right parenthesis `)` | j | Missing `)` | `)` in function call (UnaryExp), function definition (FuncDef, MainFuncDef), Stmt, PrimaryExp |
| Missing right bracket `]` | k | Missing `]` | `]` in array definition (ConstDef, VarDef,FuncFParam) and array access (LVal) |
| Mismatch between format specifiers and arguments in printf | l | Count mismatch between format specifiers and supplied expressions inside printf | `'printf' '(' StringConst {',' Exp}')' ';'` |

### Special Notes

1. For error types `i`, `j`, `k`, the "preceding nonterminal" refers to the nonterminal appearing before `;`, `)`, `]` in grammar rules. During parsing, we examine the last token of the string generated by that nonterminal, i.e., the token immediately before the expected `;`, `)`, or `]`.
2. No malicious line breaks appear in any error cases, including line breaks inside characters, string literals, function calls. Malicious line breaks refer to line breaks that interfere with correct error handling.
3. For other error types, the error line number is the line of the first token where the error can be diagnosed. Example: missing return statement in non-void function is diagnosed only when reaching the closing `}` of the function body; error line number is the line of `}`.
4. To avoid grammar ambiguity induced by erroneous test programs and incorrect AST construction: **`for` statements only contain type `h` errors. Furthermore, all errors that prevent correct AST construction will not appear.**
5. At most one error exists per source line.
6. Functions and variables cannot share identical names within the same scope.
7. For a function with redefined name, the compiler must still fully analyze its body for other errors.
8. Argument type mismatch in function calls falls into two categories:
   - Passing array to scalar parameter
   - Passing scalar to array parameter
