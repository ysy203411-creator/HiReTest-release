# Test Case Constraints
The generated test case is used to test a C-like language compiler.
1. The structure of the test case program must start with several global declarations (constants or variables), followed by several function definitions, and end with exactly one main function: int main() {{ ... return 0; }}. The main function must explicitly include return 0; at the end, and the return value must be the literal 0.
2. All identifiers (variable names, constant names, function names) must be declared before use; all identifiers in the global scope (including functions, variables, and constants) must not be duplicated; there must be no duplicate identifiers in the local scope; inner scope can shadow outer scope identifiers with the same name.
3. Variables and constants can only appear in int and char types, and their one-dimensional array types. Constants (declared with const) must be initialized at declaration, and the initial value must be a constant expression (i.e., composed only of integer literals, declared constants, and arithmetic expressions that can be evaluated at compile time). Constants cannot be assigned, and cannot appear as the left-hand side of an assignment statement.
4. If a global variable is not initialized, it defaults to 0; if it is initialized, the initial value must be a constant expression. For global variable arrays or constant arrays, if the initialization list does not provide all elements, the remaining elements are default-initialized to 0. Local variables may not be initialized (value is undefined); if initialized, the initial value can be any expression.
5. Arrays must be one-dimensional, and the length must be a non-negative integer constant expression that can be evaluated at compile time. Array access must include an index expression (e.g., a[i]), and cannot be multidimensional or omitted.
6. Functions can be of type int, char, or void. Functions with return values must have a return exp; statement on the last line.
7. Function parameter types can only be int, char, and their corresponding array types int[] and char[]. If the formal parameter is an array or string, the actual argument must be a variable array name (not a constant array, nor a regular variable).
8. Expressions support arithmetic (+ - * / %), relational (== != < > <= >=), and logical (! && ||) operations. Multiple unary operators (+, -, !) can be used consecutively, but two identical operators cannot be adjacent (e.g., --i, !!a are invalid). ! can only be used in conditional expressions. Relational and logical operations can only appear in conditional judgments and cannot be used in assignments or arithmetic statements. Operator precedence, associativity, and short-circuit evaluation rules are the same as in C.
9. Statements include assignment, expression, statement block, if, for, break, continue, return, and printf. Among these: the left-hand side of an assignment statement must be a modifiable variable (not a constant); break and continue can only appear in for loops (directly or nested); SysY programs can call three runtime library functions (these three functions do not need to be explicitly declared): getint() (no parameters, returns int), getchar() (no parameters, returns char), and printf(StringConst, Exp, ...). StringConst is a string constant, including all ASCII characters from 32 to 126; format specifiers only support %d and %c; other C language format specifiers, such as %f, are treated as ordinary characters; in the printf string constant, the only escape character that can appear is '\n', and the backslash will only appear together with 'n' as a single entity to represent a newline.
10. Lexically, identifiers consist of letters, digits, and underscores, and cannot start with a digit; reserved words (such as int, const, if, for, etc.) cannot be used as identifiers; the comment syntax is consistent with C; integer constants are non-negative decimal integers (the minus sign is a unary operator, not part of the constant).
11. The ++ and -- operators are not supported, nor are compound assignment operators (+=, =, *=, /=, %=).

## Special Cases
The following errors are allowed and must only include one or more of the clearly defined errors listed below, and the error forms must strictly conform to their definitions. If the error satisfies the constraints, it is still considered as [meeting the constraints].
b class error: Re-defining the same identifier (variable, constant, function, parameter) within the same scope.
c class error: Using an undeclared identifier (appearing in left value or function call name position).
d class error: The number of actual arguments in a function call does not match the number of formal parameters in the function definition.
e class error: The types of actual and formal parameters in a function call do not match. This includes: passing an array to a variable, passing a variable to an array, passing a char array to an int array, and passing an int array to a char array.
f class error: Using a return exp; statement with an expression in a void function.
g class error: Missing return statement at the end of an int function (including main).
h class error: Assigning to a constant or constant array element (appearing on the left-hand side of an assignment statement or in the assignment part of a for statement).
i class error: Missing semicolon ; at the end of a statement or declaration.
j class error: Missing right parenthesis ), appearing in function definition, function call, if/for condition, or parenthesized expression.
k class error: Missing right bracket ], appearing in array definition or array access.
l class error: In a printf call, the number of %d in the string does not match the number of subsequent expression parameters.
Must satisfy the following constraints:
Each line can contain at most one error;
There will be no "malicious line breaks" (such as intentional line breaks in strings, function calls, etc., which do not conform to normal code writing);
There will be no errors in for statements to avoid syntactic ambiguity;
The parts outside of errors should ensure syntactic and semantic correctness to ensure that errors can be accurately identified;
No other errors (such as illegal escape sequences, illegal identifiers, use of pointers, while, etc.) are allowed.
