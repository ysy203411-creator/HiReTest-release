# I. Overview

SysY is the source language of the compiler completed in the Compiler Technology Lab. It is a subset of the C language. A SysY source program file contains exactly one main function definition named `main`, and besides that contains several global variable declarations, constant declarations, and other function definitions. The SysY language supports the 32-bit signed `int` type and its one-dimensional array type; the `const` modifier is used to declare constants.

The SysY language itself does not provide language constructs for input/output (I/O). I/O is provided in the form of a runtime library, and library functions can be called inside functions in a SysY program. The parameter types of some SysY runtime library functions exceed the data types supported by SysY, such as strings. The SysY compiler needs to be able to handle this situation and correctly pass such parameters in a SysY program to the SysY runtime library.

- Functions: Functions may take parameters or take no parameters. Parameter types may be `int` or its one-dimensional array type; functions may return a value of type `int`, or may return no value (that is, declared as `void`). When a parameter is `int`, it is passed by value; when a parameter is an array type, what is actually passed is the starting address of the array. A function body consists of several variable declarations and statements.
- Variable/constant declarations: Multiple variables or constants may be declared in one variable/constant declaration statement, and an initialization expression may be included at declaration time. All variables/constants are required to be defined before use. Those declared outside functions are global variables/constants, and those declared inside functions are local variables/constants.
- Statements: Statements include assignment statements, expression statements (the expression may be empty), statement blocks, `if` statements, `for` statements, `break` statements, `continue` statements, and `return` statements. A statement block may contain several variable declarations and statements.
- Expressions: Basic arithmetic operations (`+`, `-`, `*`, `/`, `%`), relational operations (`==`, `!=`, `<`, `>`, `<=`, `>=`), and logical operations (`!`, `&&`, `||`) are supported. Nonzero means true, and 0 means false, while the result of a relational operation or logical operation uses 1 to represent true and 0 to represent false. **The precedence and associativity of operators as well as the evaluation rules (including short-circuit evaluation of logical operations) are consistent with the C language.**

# II. Runtime Library

A source program can perform I/O interaction through the `getint` and `printf` functions. If you want to test a test program in C, you only need to add the function declaration for `getint`, as shown in the following example:

```c
int getint() {
int t;
scanf("%d",&t);
while(getchar()!='\n');
return t;
}
```

The usage of the `printf` function is `'printf' '(' <StringConst> {, <Exp>} ')'`, where `StringConst` is a string constant terminal, whose specification refers to Chapter III, Grammar and Test Program Coverage Requirements, Section 3, Part 5, String Constants. The parsing of `<StringConst>` exceeds the data types supported by SysY, and the SysY compiler needs to be able to handle this situation.

# III. Grammar and Test Program Coverage Requirements
## 1. Grammar

The grammar of the SysY language is expressed in Extended Backus-Naur Form (EBNF, Extended Backus-Naur Form), where:
- The symbol `[...]` indicates that the enclosed item is optional
- The symbol `{...}` indicates that the enclosed item may be repeated 0 or more times
- A terminal is either a string enclosed in single quotes, or a token such as `Ident`, `IntConst`, `StringConst`
- All strings enclosed in single quotes such as `'main'` are reserved keywords
The grammar of the SysY language is given below, where `CompUnit` is the start symbol:
**Important: It is recommended to also refer to the semantic constraints in Part III of the grammar.**
```
Compilation Unit CompUnit → {Decl} {FuncDef} MainFuncDef // 1. Whether Decl exists 2. Whether FuncDef exists

Declaration Decl → ConstDecl | VarDecl // Cover both kinds of declarations

Constant Declaration ConstDecl → 'const' BType ConstDef { ',' ConstDef } ';' // 1. The braces repeat 0 times 2. The braces repeat multiple times

Basic Type BType → 'int'

Constant Definition ConstDef → Ident [ '[' ConstExp ']' ] '=' ConstInitVal // Includes ordinary variables and one-dimensional arrays

Constant Initial Value ConstInitVal → ConstExp | '{' [ ConstExp { ',' ConstExp } ] '}' // 1. Constant expression initial value 2. One-dimensional array initial value

Variable Declaration VarDecl → [ 'static' ] BType VarDef { ',' VarDef } ';' // 1. The braces repeat 0 times 2. The braces repeat multiple times

Variable Definition VarDef → Ident [ '[' ConstExp ']' ] | Ident [ '[' ConstExp ']' ] '=' InitVal // Includes ordinary constants and one-dimensional array definitions

Variable Initial Value InitVal → Exp | '{' [ Exp { ',' Exp } ] '}' // 1. Expression initial value 2. One-dimensional array initial value

Function Definition FuncDef → FuncType Ident '(' [FuncFParams] ')' Block // 1. No formal parameters 2. Has formal parameters

Main Function Definition MainFuncDef → 'int' 'main' '(' ')' Block // main function exists

Function Type FuncType → 'void' | 'int' // Cover both function types

Function Formal Parameter List FuncFParams → FuncFParam { ',' FuncFParam } // 1. The braces repeat 0 times 2. The braces repeat multiple times

Function Formal Parameter FuncFParam → BType Ident ['[' ']'] // 1. Ordinary variable 2. One-dimensional array variable

Statement Block Block → '{' { BlockItem } '}' // 1. The braces repeat 0 times 2. The braces repeat multiple times

Statement Block Item BlockItem → Decl | Stmt // Cover both kinds of statement block items

Statement Stmt → LVal '=' Exp ';' // Every type of statement must be covered

| [Exp] ';' // Both cases with and without Exp; printf function call

| Block

| 'if' '(' Cond ')' Stmt [ 'else' Stmt ] // 1. With else 2. Without else

| 'for' '(' [ForStmt] ';' [Cond] ';' [ForStmt] ')' Stmt // 1. No omission, 1 case 2. One of ForStmt and Cond omitted, 3 cases 3. Two of ForStmt and Cond omitted, 3 cases 4. ForStmt and Cond all omitted, 1 case

| 'break' ';'

| 'continue' ';'

| 'return' [Exp] ';' // 1. With Exp 2. Without Exp

| 'printf''('StringConst {','Exp}')'';' // 1. With Exp 2. Without Exp

Statement ForStmt → LVal '=' Exp { ',' LVal '=' Exp } // 1. The braces repeat 0 times 2. The braces repeat multiple times

Expression Exp → AddExp // Existence is sufficient

Conditional Expression Cond → LOrExp // Existence is sufficient

Left-value Expression LVal → Ident ['[' Exp ']'] // 1. Ordinary variable, constant 2. One-dimensional array

Basic Expression PrimaryExp → '(' Exp ')' | LVal | Number

Number Number → IntConst // Existence is sufficient

Unary Expression UnaryExp → PrimaryExp | Ident '(' [FuncRParams] ')' | UnaryOp UnaryExp // All 3 cases must be covered, and function calls also need to cover different cases of FuncRParams

Unary Operator UnaryOp → '+' | '−' | '!' Note: '!' only appears in conditional expressions // All three must be covered

Function Actual Parameter Expression FuncRParams → Exp { ',' Exp } // 1. The braces repeat 0 times 2. The braces repeat multiple times 3. Exp needs to cover array argument passing and partial array argument passing

Multiplication, Division, and Modulo Expression MulExp → UnaryExp | MulExp ('*' | '/' | '%') UnaryExp // 1. UnaryExp 2. * 3. / 4. % all need to be covered

Addition and Subtraction Expression AddExp → MulExp | AddExp ('+' | '−') MulExp // 1. MulExp 2. + needs to be covered 3. - needs to be covered

Relational Expression RelExp → AddExp | RelExp ('<' | '>' | '<=' | '>=') AddExp // 1. AddExp 2. < 3. > 4. <= 5. >= all need to be covered

Equality Expression EqExp → RelExp | EqExp ('==' | '!=') RelExp // 1. RelExp 2. == 3. != all need to be covered

Logical AND Expression LAndExp → EqExp | LAndExp '&&' EqExp // 1. EqExp 2. && all need to be covered

Logical OR Expression LOrExp → LAndExp | LOrExp '||' LAndExp // 1. LAndExp 2. || all need to be covered

Constant Expression ConstExp → AddExp Note: The Ident used must be a constant // Existence is sufficient
```

## 2. Supplementary Notes
### (1) Identifier Ident

The specification of the identifier `Ident` in the SysY language is as follows ( identifier ):
```
identifier → identifier-nondigit
| identifier identifier-nondigit
| identifier digit
```

Among them, `identifier-nondigit` is an underscore or an uppercase/lowercase letter, and `digit` is a digit from 0 to 9.
Note: Please refer to ISO/IEC 9899 http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf page 51 for the definition of identifiers. **Conventions for identifiers with the same name**:
- The scopes of global variables (constants) and local variables (constants) may overlap, and in the overlapping part the local variable (constant) takes precedence;
- The scopes of local variables with the same name may not overlap, that is, identifiers (constants/variables) with the same name may not appear in the same Block;
- In different scopes, in the SysY language a variable (constant) name may be the same as a function name;
- Reserved keywords may not be used as identifiers.
```
// Legal example
int main() {
	int a = 0;
	{
		int a = 1;
		printf("%d",a); // Output 1
	}
	return 0;
}
```
```
// Illegal example
int main() {
	int a = 0;
	{
		int a = 1;
		int a = 2; // Illegal!
	}
	return 0;
}
```
### (2) Comments
The specification of comments in the SysY language is consistent with the C language, as follows:
- Single-line comment: Starts with the sequence `//`, ends at a newline character, and does not include the newline character.
- Multi-line comment: Starts with the sequence `/*`, and ends when `*/` appears for the first time, including the ending `*/`.
Note: Please refer to ISO/IEC 9899 http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf page 66 for the definition of comments.
### (3) Numeric Constants
In the SysY language, numeric constants may be integer constants `IntConst`, whose specification is as follows (corresponding to integer-const):
```
Integer constant integer-const → decimal-const | 0

• decimal-const → nonzero-digit | decimal-const digit

• nonzero-digit is a digit from 1 to 9.
```
Note: Please refer to ISO/IEC 9899 http://www.open-std.org/jtc1/sc22/wg14/www/docs/n1124.pdf page 54 for the definition of integer constants, and on this basis ignore all suffixes.
### (4) String Constants
The definition of `<StringConst>` in the SysY language is as follows:
```
<FormatChar> → %d
<NormalChar> → ASCII characters with decimal codes 32,33,35-126, '\' (code 92) appears if and only if it is '\n'
<Char> → <FormatChar> | <NormalChar>
<StringConst> → '"'{<Char>}'"'
```
In a string, **only one kind of escape character `\n` may appear**, used to indicate a line break here. Other escape cases need not be considered.
# IV. Semantic Constraints

The set of programs conforming to the above grammar is a superset of the set of legal SysY language programs. The semantic constraints of the SysY language are further given below.
## Runtime Library
1. **In order to reduce development difficulty, it is guaranteed that in all test programs `getint` and `printf` will only appear as runtime library calls and will not appear as custom variable/function identifiers.**
2. The `printf` function does not add a newline by default.
3. Similar to `printf` in the C language, in an output statement, format characters will be replaced by the corresponding identifiers, and ordinary characters will be output as they are.
## static Keyword
1. The `static` keyword is used to modify **static local variables**, and will not appear in global variable definitions.
2. For a variable declaration modified with `static`, if it has an initial value, the initial value can be computed at compile time.
3. For a variable declaration modified with `static`, **even if no initial value is assigned at declaration, the compiler will initialize it to 0**.
4. A variable specified by the `static` keyword is initialized only once, and **retains its state when the function is called later**, and will not be destroyed when leaving the function. However, the scope of the variable it modifies is limited to the interior of the function in which it is declared.

## Compilation Unit CompUnit
```
Compilation Unit CompUnit → {Decl} {FuncDef} MainFuncDef

Declaration Decl → ConstDecl | VarDecl
```
1. Top-level variable/constant declaration statements of `CompUnit` (corresponding to `Decl`) and function definitions (corresponding to `FuncDef`) may not repeatedly define identifiers with the same name (`Ident`), even if the identifier types are different.
2. The scope of variable/constant/function declarations of `CompUnit` starts from the declaration and extends to the end of the file.
## Constant Definition ConstDef
```
Constant Definition ConstDef → Ident [ '[' ConstExp ']' ] '=' ConstInitVal
```
1. `ConstDef` is used to define a symbolic constant. The `Ident` in `ConstDef` is the identifier of the constant. After `Ident` and before `=`, there is an optional one-dimensional array and one-dimensional array length definition part, and after `=` is the initial value. A constant must have a corresponding initial value.
2. If the one-dimensional array and one-dimensional array length definition part of `ConstDef` does not exist, it means a single variable is defined.
3. If the one-dimensional array and one-dimensional array length definition part of `ConstDef` exists, it means an array is defined. Its semantics are consistent with the C language, and the lower bound of each dimension is numbered from 0.
4. Each `ConstExp` representing a dimension length in `ConstDef` must be evaluable at compile time to a **nonnegative integer**.

## Variable Definition VarDef
```
Variable Definition VarDef → Ident [ '[' ConstExp ']' ] | Ident [ '[' ConstExp ']' ] '=' InitVal
```
1. The definition of a variable is basically the same as that of a constant, but a variable may have no initial value part, in which case its actual initial value at runtime is undefined.
## Initial Value ConstInitVal / InitVal
```
Constant Initial Value ConstInitVal → ConstExp | '{' [ ConstExp { ',' ConstExp } ] '}'

Variable Initial Value InitVal → Exp | '{' [ Exp { ',' Exp } ] '}' | StringConst
```
1. The initial value expression of any constant must be a constant expression `ConstExp`.
2. **A constant must have an initial value. A constant array does not need every element to have an initial value, but the compiler needs to set the unassigned parts to 0.**
3. The initial value expression of a global variable must also be a constant expression `ConstExp`. However, the initial value expression of a local variable is `Exp`, and already declared variables may be used.
4. For a single constant or variable, the initial value must also be a single expression. (An expression includes cases such as a single number, a single variable, a single constant, etc.)
5. **For global variables, if no initial value is given, then all should be set to 0. Local variables do not need this.**
## Function Formal Parameter FuncFParam and Actual Parameter FuncRParams
```
Function Formal Parameter List FuncFParams → FuncFParam { ',' FuncFParam }

Function Actual Parameter List FuncRParams → Exp { ',' Exp }
```
1. `FuncFParam` defines one formal parameter of a function. When the optional part after `Ident` exists, it indicates an array definition.
2. The syntax of a function actual parameter is `Exp`. For ordinary variables, pass-by-value is followed; for parameters of array type, the formal parameter receives the address of the actual parameter array and indirectly accesses the elements in the actual parameter array through the address.
3. An ordinary constant may serve as a function parameter, but a constant array may not. For example, `const int arr[3] = {1,2,3}`; the constant array `arr` may not be passed as a parameter into a function.
4. When a function is called, it must be ensured that the actual parameter type is consistent with the formal parameter type. See the following example for details.
```
void f1(int x){
	return ;
}

void f2(int x[]){
	return ;
}
int main(){
	int x = 10;
	int t[5] = {1, 2, 3, 4, 5};
	f1(x); // Legal
	f1(t[0]); // Legal
	f1(t); // Illegal
	f2(t); // Legal
}
```
## Function Definition FuncDef
```
Function Definition FuncDef → FuncType Ident '(' [FuncFParams] ')' Block
```
1. `FuncDef` represents a function definition. The `FuncType` in it specifies the return type. When the return type is `int`, all branches in the function should contain a `return` statement with `Exp`. The return value of a branch that does not contain a `return` statement is undefined. When the return type is `void`, only `return` statements without a return value may appear in the function.
2. The semantics of `FuncFParams` are as above.
## Statement Block Block
1. `Block` represents a statement block. A statement block creates a scope, and the lifetime of constants and variables declared in the statement block is within that statement block.
2. Inside a statement block, a variable or constant with the same name as outside the statement block may again be defined (through a `Decl` statement), and its scope starts from the definition and ends at the end of the statement block, hiding the variable or constant with the same name outside the statement block.
3. In order to reduce development difficulty, **it is guaranteed that in all test programs, the last statement of the Block of a function with a return value will explicitly give a return statement; otherwise it is treated as the error “no return statement”**. At the same time, when students write and upload sample programs, they also need to ensure this.
4. The return value of the `main` function can only be the constant 0.
## Statement Stmt
1. The `if` type statement in `Stmt` follows nearest-match.
2. A single `Exp` may serve as a `Stmt`. This `Exp` will be evaluated, but the value obtained will be discarded.
## Left-value LVal
1. `LVal` represents an expression with a left value, and may be a variable or an array element.
2. When `LVal` represents an array, the number of square brackets must be the same as the number of dimensions of the array variable (that is, locate the element).
3. When `LVal` represents a single variable, the following square brackets may not appear.
## Exp and Cond
1. **In SysY, `Exp` represents an expression of type int or void; `Cond` represents a conditional expression, so it is defined as `LOrExp`. Among the unary operators of the former, `!` does not appear, while the latter may contain it.**
2. `LVal` must be a variable or constant defined in the current scope before this `Exp` statement; for an `LVal` on the left side of an assignment, it must be a variable.
3. The function call form is `Ident '(' FuncRParams ')'`, where `FuncRParams` represents the actual parameters. The types and number of actual parameters must exactly match the formal parameters of the function definition corresponding to `Ident`.
4. The precedence and associativity of operators in SysY are consistent with the C language. The definitions of precedence and associativity have already been reflected in the above SysY grammar.
## Unary Expression UnaryExp
1. Two adjacent `UnaryOp`s may not be the same, such as `int a = ++-i;`, but `int a = +-+i;` is feasible.
2. `UnaryOp` being `!` may only appear in conditional expressions.
## Constant Expression ConstExp
1. **In SysY, `ConstExp` represents an expression of type int.**
2. `ConstExp` is evaluable at compile time. The `ident` involved in `ConstExp -> AddExp` must all be constants, that is, only constants, constants that can obtain specific values, and arithmetic expressions composed of them that can be evaluated within the compiler may be used.

## Special Notes
1. The “previous nonterminal” in error types i, j, k emphasizes the nonterminal symbol appearing before `;`, `)`, `]` in the grammar rule. In analysis, what is handled is the last symbol of the terminal symbol string produced by that nonterminal, that is, the word at the position where `;`, `)`, `]` should normally appear.
2. All errors will not involve malicious line breaks, including line breaks in characters and strings, function calls, and so on. So-called malicious line breaks refer to **line breaks that make error handling difficult to perform correctly**.
3. For other types of errors, the error line number is based on the line number of the first symbol at which it can be determined that an error has occurred. For example, for the error of a function with a return value lacking a return statement, the error can be determined only when `}` at the end of the function is recognized and no return statement has appeared, and the reported line number is the line number of `}`.
4. In order to avoid syntax ambiguity caused by errors in test programs and cause the syntax tree to be built in an erroneous way, we guarantee that: **the `for` statement will not contain any error other than type h. Furthermore, we guarantee that all errors that would prevent the syntax tree from being built correctly will not appear.**
5. There is at most one error per line.
6. In the same scope, **functions and variables may not have the same name**.
7. For a function with a duplicate name, whether there are other errors inside the function should still be fully analyzed.
8. For parameter type mismatch when calling a function, there are the following mismatches:
- Passing an array to a variable.
- Passing a variable to an array.

Regarding the scope number, that is, the number of scopes entered before entering this scope plus 1. When entering the global scope, the number of scopes entered is 0, so the global scope number is 1.
Regarding symbol table output, output in increasing order of scope number, first outputting all symbols in the scope with the smaller number. For the same scope, output in the order in which the symbols are declared.
Function parameters belong to the scope inside the function.
`main` is a reserved keyword and is not included in the symbol table.
