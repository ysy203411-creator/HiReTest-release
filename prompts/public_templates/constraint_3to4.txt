Generated test cases are used to test a class C language compiler.
1. The program structure of a test case must start with several global declarations (constants or variables), optionally followed by several function definitions, and must end with exactly one main function: int main() {{ ... return 0; }}. The main function must explicitly include return 0; at its end, and the return value must be the literal 0.
2. All identifiers (variable names, constant names, function names) must be declared before use; all identifiers in the global scope (including functions, variables, and constants) must not be duplicated; there must be no duplicate identifiers in the local scope; inner scopes may shadow outer scope identifiers with the same name.
3. Constants (declared with const) must be initialized at declaration, and the initial value must be a constant expression (i.e., composed solely of integer literals, declared constants, and arithmetic expressions that can be evaluated at compile time); constants cannot be assigned to, and cannot appear as l-values on the left side of an assignment statement.
4. Global variables that are not initialized default to 0; if initialized, the initial value must be a constant expression. For global variable arrays or constant arrays, if the initialization list does not provide all elements, the remaining elements are default-initialized to 0. Local variables may be uninitialized (with undefined values); if initialized, the initial value can be any expression.
5. The use of static is allowed to modify local variables, but not global variables. Static local variables that are not initialized default to 0 and are initialized only once; their scope remains limited to the function in which they are defined.
6. Arrays must be one-dimensional, and their length must be a non-negative integer constant expression that can be evaluated at compile time. Array access must include an index expression (e.g., a[i]), and cannot be multidimensional or omitted.
7. Functions can be of type int or void. For int functions, the last line of the function body must explicitly be return exp; even if it is unreachable. Void functions can only contain return; (without an expression), and may omit the return statement. Any number of return statements can appear at any position in a function, and they may be unreachable.
8. Function parameter types can only be int or int[]. If the formal parameter is int, the actual argument must be an integer expression (variable, constant, or array element); if the formal parameter is int[], the actual argument must be a variable array name (not a constant array, nor a regular variable).
9. Expressions support arithmetic (+ - * / %), relational (== != < > <= >=), and logical (! && ||) operations. Multiple unary operators (+, -, !) can be used consecutively, but two identical operators cannot be adjacent (e.g., --i, !!a are invalid). The ! operator can only be used in conditional expressions. The results of relational and logical operations are 1 (true) or 0 (false); in conditional judgments, non-zero values are considered true, and 0 is considered false; the precedence, associativity, and short-circuit evaluation rules are the same as in C.
10. Statements include assignment, expression, statement block, if, for, break, continue, return, and printf. Among these: the left side of an assignment statement must be a modifiable variable (not a constant); break and continue can only appear in for loop bodies (directly or nested); SysY programs can call two runtime library functions: getint() (no parameters, returns int) and printf(StringConst, Exp, ...). StringConst is a string constant, containing only ASCII characters (codes 32, 33, 35–126) and escape sequences \\n; format specifiers only support %d, and the number of %d must match the number of subsequent integer expression parameters. Although the string constant type exceeds SysY (only int and int[] are supported), the compiler must correctly handle such calls. These two functions can be used without explicit declaration. Lexically, identifiers consist of letters, digits, and underscores, and cannot start with a digit; reserved words (such as int, const, if, for, etc.) cannot be used as identifiers; the comment syntax is consistent with C.
11. The ++ and -- operators are not supported, nor are compound assignment operators (+=, =, *=, /=, %=).
13. Relational operators (== != < > <= >=) and logical operators (! && ||) [can only] appear in the condition expressions of if and for statements; they cannot appear on the right side of assignment statements, in arithmetic expressions, function parameters, or return values of return statements.
II. Constraints for error programs
Error programs are used to test the error detection capability of student compilers and must contain only one or more of the following clearly defined errors, and the error forms must strictly conform to their definitions.
a class error: A single & or | appears in the source program, which should be considered an illegal symbol (correct should be && or ||). The use of && or || must follow their usage specifications, and they can only appear in conditional expressions.
b class error: A duplicate identifier with the same name is defined in the same scope (including variables, constants, functions, and parameters).
c class error: An undeclared identifier is used (appearing in the left value or function call name position).
d class error: The number of actual arguments in a function call does not match the number of formal parameters in the function definition.
e class error: The types of actual arguments and formal parameters in a function call do not match. This includes: passing a variable to an array formal parameter, or passing an array (variable or constant) to an int formal parameter.
f class error: A return exp; statement with an expression is used in a void function.
g class error: The int function (including main) lacks a return statement at the end.
h class error: Assignment to a constant or constant array element (appearing on the left side of an assignment statement or in the assignment part of a for statement).
i class error: Missing semicolon ; at the end of a statement or declaration.
j class error: Missing right parenthesis ), appearing in function definitions, function calls, if/for conditions, or parenthesized expressions.
k class error: Missing right bracket ], appearing in array definitions or array accesses.
l class error: In a printf call, the number of %d in the string does not match the number of subsequent expression parameters.
Error programs must satisfy the following constraints:
Each line can contain at most one error;
"Malicious line breaks" (such as intentional line breaks in strings, function calls, etc., to make errors hard to locate) are not allowed;
Only h class errors are allowed in for statements; other errors will not appear in for structures to avoid syntactic ambiguity;
The parts outside of errors should ensure syntactic and semantic correctness to ensure accurate error detection;
No other errors (such as illegal escape sequences, illegal identifiers, use of pointers, while, etc., unsupported features) are allowed.
