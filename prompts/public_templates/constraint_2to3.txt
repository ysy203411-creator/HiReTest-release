The generated test cases are used to test a class C language compiler.
1. The program structure of the test case must start with several global declarations (constants or variables), followed by several function definitions, and end with exactly one main function: int main() {{ ... return 0; }}. The main function must explicitly include return 0; at its end, and the return value must be the literal 0.
2. All identifiers (variable names, constant names, function names) must be declared before they are used; all identifiers in the global scope (including functions, variables, and constants) must not be duplicated; there must be no duplicate identifiers in the local scope; inner scope can shadow identifiers with the same name in the outer scope.
3. Constants (declared with const) must be initialized at the time of declaration, and the initial value must be a constant expression (i.e., composed only of integer literals, declared constants, and arithmetic expressions that can be evaluated at compile time); constants cannot be assigned, and cannot appear as the left-hand side of an assignment statement.
4. Global variables that are not initialized default to 0; if initialized, the initial value must be a constant expression. For global variable arrays or constant arrays, if the initialization list does not provide all elements, the remaining elements are default-initialized to 0. Local variables may not be initialized (their values are undefined); if initialized, the initial value can be any expression.
5. The use of static is allowed to modify local variables, but not for global variables. A static local variable that is not initialized defaults to 0 and is initialized only once; its scope remains limited to the function in which it is defined.
6. Arrays must be one-dimensional, and their length must be a non-negative integer constant expression that can be evaluated at compile time. Array access must include an index expression (e.g., a[i]), and cannot be multidimensional or omitted.
7. Functions can be of type int or void. For an int function, the last line of the function body must explicitly be return exp; even if it is unreachable. A void function can only contain return; (without an expression), and may not contain a return statement. Any number of return statements can appear at any position in a function, and they may be unreachable.
8. The types of function parameters can only be int or int[]. If the formal parameter is int, the actual argument must be an integer expression (variable, constant, or array element); if the formal parameter is int[], the actual argument must be a variable array name (not a constant array, nor a regular variable).
9. Expressions support arithmetic (+ - * / %), relational (== != < > <= >=), and logical (! && ||) operations. Multiple unary operators (+, -, !) can be used consecutively, but two identical operators cannot be adjacent (e.g., --i, !!a are invalid). The ! operator can only be used in conditional expressions. The results of relational and logical operations are 1 (true) or 0 (false); in conditional judgments, non-zero values are considered true, and 0 is considered false; the precedence, associativity, and short-circuit evaluation rules are the same as in C.
10. Statements include assignment, expression, statement block, if, for, break, continue, return, and printf. Among these: the left-hand side of an assignment statement must be a modifiable variable (cannot be a constant); break and continue can only appear in for loop bodies (directly or nested); SysY programs can call two runtime library functions: getint() (no parameters, returns int) and printf(StringConst, Exp, ...). StringConst is a string constant, containing only ASCII characters (codes 32, 33, 35–126) and escape sequences \\n; the format specifier only supports %d, and the number of %d must match the number of subsequent integer expression parameters. Although the string constant type exceeds SysY (only int and int[] are supported), the compiler must correctly handle such calls. These two functions can be used without explicit declaration. Lexically, identifiers consist of letters, digits, and underscores, and cannot start with a digit; reserved words (such as int, const, if, for, etc.) cannot be used as identifiers; the comment syntax is consistent with C.
11. The ++ and -- operators are not supported, nor are compound assignment operators (+=, =, *=, /=, %=).
12. The types and number of parameters in a function call must match the function declaration.
13. Relational operators (== != < > <= >=) and logical operators (! && ||) [can only] appear in the condition expressions of if and for statements; they cannot appear on the right-hand side of assignment statements, in arithmetic expressions, function parameters, or the return values of return statements.
II. Constraints for error programs
Error programs are used to test the error detection capability of student compilers and must contain only one or more of the following clearly defined errors, and the error forms must strictly conform to their definitions.
a-type error: A single & or | appears in the source program, which should be considered an illegal symbol (it should be && or ||). The use of && or || must follow their usage rules and can only appear in conditional expressions.
i-type error: Missing semicolon ; at the end of a statement or declaration.
j-type error: Missing right parenthesis ), which appears in function definitions, function calls, if/for conditions, or parenthesized expressions.
k-type error: Missing right bracket ], which appears in array definitions or array accesses.
Error programs must satisfy the following constraints:
Each line can contain at most one error;
There will be no "malicious line breaks" (e.g., intentional line breaks in strings, function calls, etc., to make errors hard to locate);
There will be no errors in for statements to avoid syntactic ambiguity;
The parts of the program outside of errors should ensure syntactic and semantic correctness to ensure that errors can be accurately identified;
No other errors (such as illegal escapes, illegal identifiers, use of pointers, while, etc.) are allowed except those listed above.
